## Executive Summary
B3.1 implements true geometric distance and angular calculations within concept space for intent-driven question-chunk matching. This represents a fundamental shift from traditional TF-IDF similarity to geometric concept space retrieval aligned with the thesis framework of concepts as centroids of convex balls.

---

## 1. Architectural Vision

### Core Innovation
Transform intent matching from keyword-based similarity to geometric distance calculations within concept-centered convex balls, where both questions and chunks exist as coordinate points in the same multi-dimensional concept space.

### Theoretical Foundation
```
Concept Space: n-dimensional space where each dimension represents a concept
Question Point: Q = (q₁, q₂, ..., qₙ) where qᵢ = membership in concept i
Chunk Point: C = (c₁, c₂, ..., cₙ) where cᵢ = membership in concept i
Intent Vector: I = directional vector representing question intent
Geometric Distance: d(Q,C,I) = intent-weighted Euclidean distance
```

## 3. Core Design Decisions

### Decision 1: Geometric Distance Calculation
**Choice**: Implement true Euclidean distance with intent weighting
**Rationale**: Aligns with thesis framework of geometric concept spaces
**Trade-off**: Computational complexity vs. theoretical alignment

### Decision 2: Intent Vector Representation
**Choice**: Multi-dimensional intent vector based on intent categories
**Rationale**: Captures directional preference within concept space
**Alternative Considered**: Single intent weight (rejected as too simplistic)

### Decision 3: Angular Analysis from Multiple Centroids
**Choice**: Calculate angles from each primary concept centroid
**Rationale**: Provides multi-perspective geometric analysis
**Impact**: Richer matching signals at cost of computation

### Decision 4: Concept Ball Constraint
**Choice**: Pre-filter chunks to relevant concept balls before distance calculation
**Rationale**: Ensures matching within convex boundaries per thesis design
**Benefit**: Improved precision and computational efficiency

## 4. Processing Pipeline Architecture

### Phase 1: Geometric Mapping
```
A3 chunks → Extract concept memberships → Map to n-dimensional coordinates
B2.5 questions → Extract fuzzy memberships → Map to same n-dimensional space
B2.1 intent → Extract intent scores → Construct intent direction vector
```

### Phase 2: Concept Ball Filtering
```
Primary concepts from B2.5 → Identify relevant concept balls
Filter chunks by ball membership → Reduce search space
Maintain geometric coherence → Ensure convex ball constraints
```

### Phase 3: Geometric Calculation
```
For each chunk in relevant balls:
  - Calculate base Euclidean distance
  - Apply intent vector weighting
  - Compute angular separations from centroids
  - Generate composite geometric score
```

### Phase 4: Ranking and Output
```
Sort by geometric proximity → Apply distance thresholds
Include geometric metadata → Preserve calculation transparency
Format for downstream consumption → Maintain compatibility
```

## 5. Mathematical Framework

### Coordinate System
```python
Question: Q = [m₁, m₂, ..., mₙ] where mᵢ ∈ [0,1] (membership scores)
Chunk: C = [c₁, c₂, ..., cₙ] where cᵢ ∈ [0,1] (membership scores)
Intent: I = [i₁, i₂, ..., i₅] (normalized intent vector)
```

### Distance Calculation
```python
Base Distance: d_base = ||Q - C||₂
Intent Alignment: α = cos(θ) where θ = angle between I and (C-Q)
Weighted Distance: d_final = d_base / (0.5 + 0.5α)
```

### Angular Analysis
```python
For each concept centroid Kᵢ:
  θᵢ = arccos((Q-Kᵢ)·(C-Kᵢ) / (||Q-Kᵢ|| × ||C-Kᵢ||))
```

## 7. Performance Considerations

### Computational Complexity
- **Coordinate Mapping**: O(n) where n = number of concepts
- **Distance Calculation**: O(m×n) where m = number of chunks
- **Angular Analysis**: O(m×k) where k = primary concepts
- **Total**: O(m×n) dominated by distance calculations

### Optimization Strategies
1. **Vectorized Operations**: Use NumPy for batch calculations
2. **Early Filtering**: Apply concept ball constraints first
3. **Caching**: Store computed coordinates between calls
4. **Parallel Processing**: Calculate distances in parallel for large sets
